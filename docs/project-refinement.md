# Project Refinement

Use this guide after Day 1 and before Day 2. Complete one deck per team for one main Flow. An unfinished Flow or an idea that you could not start is a valid response.

Think of the deck as a project check-up sheet: it shows what your team tried, what happened and where support would help.

## Complete the five core slides

1. **Our Project & Team:** name the Flow, team roles, current status and main support need.
2. **The Problem & Expected Outcome:** explain the current task, pain point, Flow boundary and observable success checks.
3. **How Our Flow Works:** show the trigger, important steps, branches, apps, inputs, outputs and human checks. Mark each step as **Built**, **Planned** or **Blocked**.
4. **What We Built & Tested:** compare expected and actual results for the cases you really tested. Record anything that remains untested.
5. **Our Main Blocker:** describe one issue, where it occurs, how to reproduce it and what your team has already tried.

Use Appendix A for another issue. Use Appendix B for a readable screenshot, diagram or short output excerpt. Duplicate these appendix slides only when they help someone understand the project.

## Choose one honest current status

- Not started
- Design only
- Partly built
- Built but not tested
- Tested with issues
- Tested successfully for stated cases

Use the same status throughout the deck. A successful status applies only to the cases your team tested. It does not prove production readiness.

## Record evidence carefully

- Separate what you planned, built and tested.
- Compare the expected result with the actual result in the destination app or file.
- A **Succeeded** run can still produce the wrong output.
- Use **Not yet tested**, **Unknown**, **Not applicable** or **No evidence yet** when they describe the current state.
- Label screenshots and output excerpts so another person can connect them to the relevant test or issue.

## Protect information

Use synthetic or training-approved information. Remove customer details, personal information and unrelated screen content. Use role labels instead of real recipient addresses.

Do not include passwords, access tokens, connection credentials, full run payloads or complete operational datasets. Do not export or share a Flow package only to complete this deck.

## Save and share through the confirmed channel

Keep the completed deck in an approved team location. The facilitator or coordinator will confirm the submission channel and deadline. This public website does not accept uploads, and the template does not create a weekly assignment or progress log.

The completed deck helps the instructor understand common support needs. It does not confirm tenant access, production feasibility or business impact.
