# Operations Day 2: Repair, test and verify

Use prepared Flows to repair small problems in a fictional **Operations Request Desk**. Work in pairs, compare the expected result with the actual result, and ask another pair to reproduce your test. Your workbook and training resources belong to your pair.

The live exercises are designed to start from prepared Flows that handle the routine work. Your task is to find the first place where the result changes, make a small repair, and test the same case again. Like a parcel delivery, a completed journey is only useful when the address and contents are correct.

> **Preparation status:** This learner website contains the learning instructions and synthetic resources. Learner Flow packages are not released. Begin live practice only with an approved starter and confirmed account access; check the separate export and rehearsal states on [Downloads](./downloads.md#starter-flow-status). A fixture or example result is not a completed Flow run.

The day contains **330 teaching minutes**. Required activities stay inside these blocks.

## One diagnostic method

1. **Expected result:** state what the request should produce.
2. **Actual result:** inspect the row, received message, file or preview.
3. **First divergence:** trace action inputs and outputs until you find the first mismatch.
4. **Repair:** change the smallest relevant setting.
5. **Retest:** rerun the same test before changing the test data.

Keep a brief evidence note for each repair: expected result, actual result, first divergence, change and retest result. A second pair checks the evidence during the exercise. There is no individual consultation queue.
